# まもっち ESP32-S3 AP

トンネル内に並べて「位置の目印」にする Wi-Fi AP のファームウェア。
ウォッチはこの AP に**接続しない**。スキャンして電波の強い順に2つの BSSID（`mac01` / `mac02`）をサーバーへ送り、
サーバーがその BSSID の設置距離から位置を推定する（仕組みは `SPEC.md` §6.2）。

## 何をするか

| 機能 | 内容 |
|---|---|
| softAP | SSID `MAMOTCHI-<AP_LABEL>`、パスワード付き、接続上限 1。ビーコンを出し続けるだけ |
| 送信出力 | `TX_POWER_DBM`（-1〜21 dBm）。トンネルは電波が遠くまで届くので低めから調整する |
| heartbeat | 上り回線（現場 Wi-Fi）があれば 30 秒ごとに `POST /api/ap_heartbeat`。初回で `ap_nodes` に自動登録 |
| 上り回線なし | AP としてだけ動く。起動時にシリアルへ出る BSSID を管理画面の「AP位置設定」に手で登録する |

## 準備（1回だけ）

1. Supabase の SQL Editor で `supabase/ap_nodes.sql` を実行する
2. Vercel の環境変数に `AP_SHARED_TOKEN`（長いランダム文字列）を追加して再デプロイする
3. Arduino IDE で「ボードマネージャ」から **esp32 by Espressif Systems** を入れる

## 1台ごとの書き込み

1. `config.example.h` を `config.h` にコピーする（`config.h` は Git に入らない）
2. `config.h` を書き換える
   - `AP_LABEL`: 表示名。距離が分かる名前がおすすめ（例 `A050` = 50m 地点）
   - `AP_DISTANCE_M`: 入口からの距離[m]。初回登録時の初期値（以後は管理画面で変える）
   - `AP_CHANNEL`: 隣り合う AP で 1 → 6 → 11 → 1 … と変える（上り回線ありだと上り回線のチャンネルに揃う）
   - `UPLINK_SSID` / `UPLINK_PASSWORD` / `AP_TOKEN`: heartbeat を使う場合だけ
3. ボードは **ESP32S3 Dev Module**（またはお使いの S3 ボードの定義）を選び、USB でつないで書き込む
4. シリアルモニタ（115200bps）に出る `BSSID=…` を控える

## 設置後の確認

1. ダッシュボードの「ESP32 AP」に行が出て「稼働中」になる（heartbeat ありの場合）
2. 「入口からの距離 [m]」を確認して「保存」→ トンネルマップの下端に AP が並ぶ
3. ウォッチを持って各 AP の前に立ち、マップの位置が合うか確かめる
4. 隣の AP より 2 台以上先の AP がよく `mac01` に入るなら、`TX_POWER_DBM` を下げて書き込み直す

## 間隔の目安（シミュレーション、送信 5 秒・電波ノイズ 6dB）

| AP 間隔 | 0〜500m の台数 | 平均誤差 | 誤差の大きい側（90%点） |
|---|---|---|---|
| 100m | 6 | 19m | 39m |
| 50m | 11 | 11m | 23m |
| 25m | 21 | 8m | 15m |

ウォッチのスキャンが 30 秒おきになると（Android のスキャン回数制限）、100m 間隔で平均 30m、50m 間隔で 17m まで悪化する。

## 注意

- `SERVER_ROOT_CA` を入れない間は TLS 証明書を検証しない（`setInsecure()`）。試験用。本番は CA を入れる
- 上り回線の AP と同じ場所に置くと、上り回線の電波が `mac01` を奪うことがある。ウォッチ側で SSID が `MAMOTCHI-` で始まる AP だけを使うようにすると防げる
- 電源が落ちた AP はマップで灰色＋×になる（heartbeat が 90 秒途絶）。位置推定からは自動では外さないので、撤去したら管理画面で「使わない」にする
